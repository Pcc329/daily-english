📖 今日文法重點 — 被動語態 Passive Voice（was/were + 過去分詞）
資安操作的主角常是「動作本身」，不是「誰做的」，所以英文技術文件大量使用被動語態。

✅ 權限被授予：Full access was granted to the public key by mistake.
✅ 權限被撤銷：The write permissions were revoked from the anon role.
✅ 個資被保護：Contact data is masked before it is returned.
✅ 存取被拒絕：The request was denied with a permission error.

主動 vs 被動對照：
主動：We revoked the permissions.（我們撤銷了權限）
被動：The permissions were revoked.（權限被撤銷了 — 不強調誰做，強調結果）

朗讀練習
段落一 — 我們發現了什麼？（We found that…）

Today I planned to migrate the contacts table.
During the health check, I found a serious problem.
The public key had full permissions on many tables.
It could read private contact data.
It could even delete or empty entire tables.
The front end looked safe, but the data was not locked.

段落二 — 風險是什麼？（被動語態 Passive）

The public key is written in the front end, so anyone can read it.
Because of this, the contact data could be exposed to the public.
The records could also be deleted or changed.
This is a serious privacy risk.
Sensitive data should never be exposed through a public key.

段落三 — 我們怎麼修的？（were revoked）

First, all permissions were revoked from the contacts table.
Then the write permissions were removed from the business tables.
Only the read permission was kept, because the front end still needs to display data.
Finally, the change was verified by testing the public key directly.

段落四 — 兩道鎖的觀念（Two independent locks）

Database access is protected by two independent locks.
The first lock is the table permission.
It decides whether a role can touch the table at all.
The second lock is row-level security.
It decides which rows a role can see.
If either lock is closed, the access is blocked.
The contacts table is now locked by both.

段落五 — 模擬主管問答（Did you…?）

Did you find a security problem?
Yes, I did.

Were the permissions too wide?
Yes, they were.

What was revoked?
The write and delete permissions were revoked from the public key.

Is it safe now?
Yes, it is. It was verified by a direct test.

請跟讀三次：

I found that the public key had too many permissions.
The write and delete rights were revoked.
Only the read permission was kept, so the front end still works.

進階版：
Database access is protected by two independent locks: table permissions and row-level security.
The contact data is now locked by both, and the fix was verified by testing the public key directly.
今日總結

今天的英文主題是如何用被動語態描述資安修補。

中文裡你說的是：
「公開金鑰權限開太大，聯絡人個資可能外洩；我們撤銷了寫入與刪除權限，只保留讀取，並實測驗證修好了。」

The public key had too many permissions, so the contact data could be exposed.
The write and delete permissions were revoked, and only read access was kept.
The fix was verified by testing the public key directly.

這就是你的每日英文資料庫真正有價值的地方：
把資安操作用被動語態說清楚 — 這正是技術文件與資安報告最常見的語態。
